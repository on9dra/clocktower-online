# 真实界面试玩台

两种用法，同一套工具：
- **开发者验证改动**（主会话自己用）：一条命令直接摆出要看的局面（剧本、模式、座位角色、第几夜哪一步 / 第几天），几秒就绪，不用从建房重放。
- **测试员试玩**（便宜的子代理）：像真人一样通过真实页面把一局从建房玩到结束。

直接调接口测不出错位、遮挡、点不到和引导不清，所以页面上每一下都是真的鼠标点击，点之前先做命中测试。局面是引擎造的，看和点仍然是真页面。

## 验证一个改动：先用这条

```
node tools/uitest/ui.mjs 3912 preset script=tb mode=one n=7 at=day1
```

- rig 没在跑会自动在后台起一台（名字 `auto3910`，服务 3910、调试 3911、控制 3912；一个半小时没人用自己收摊）。几个会话同时用时各占一个十位：3910、3920、3930…（控制端口 = 基准 + 2）。
- 返回：用了几秒、停在哪一步、座位表（谁是什么角色）、打开了哪几台设备、每台一张截图（等转场播完才截）。
- 快照是 rig 启动时拷的；之后改了代码用 `sync`（见下），不用重起。

### 局面参数（`preset`，都是 键=值，详见 `preset.mjs` 开头）

| 参数 | 例子 | 说明 |
|---|---|---|
| `script` | `tb` `bmr` `snv` `tools/uitest/scripts/wugang.json` | 默认 tb |
| `mode` | `online` `many` `one` | 线上 / 线下多设备 / 线下单设备，默认 online |
| `n` | `7` | 人数，默认 7 |
| `roles` | `imp,poisoner,chef,empath,monk,drunk>slayer,soldier` | 按座位指定全部角色（`>` 后是酒鬼以为的角色） |
| `with` | `juggler` `imp@3` | 只指定几个，其余按规则抽（固定随机种子，同样参数每次一样；`seed=` 换一组） |
| `at` | `lobby` `night1` `night2:imp` `night1:dawn` `day1` `day1:nominate=3>1` `day1:slay=3>1` `end:good` | 停在哪：某夜某角色那一步（他还没选）、天亮前确认、第几天、提名中、等猎手裁定、结束 |
| `pick.<角色>[@夜]` | `pick.imp@2=7` `pick.fortuneteller=2,3` | 那个角色选谁；不写就自动选合规的（不选自己，邪恶不对队友下手） |
| `dead` | `2,4` | 到了以后把这几个人标成死亡 |
| `phones` | `all` `none` `1,3` | 线上 / 多设备开哪几台玩家手机（`p<座位号>`）；默认夜里轮到的那个人 |
| `stsize` `phonesize` | `375x664` `844x390` | 设备尺寸，默认说书人 1280x800、手机 375x664 |
| `shot=0` `pass=0` | | 不截图；单设备第一夜保留「传阅身份」那张卡 |

常用的三个（实测：造局 0.7 秒，页面就绪 2–3.5 秒，连截图 4–6 秒；rig 第一次启动另加 3–5 秒）：
```
node tools/uitest/ui.mjs 3912 preset script=tb mode=one n=7 at=day1                  # 暗流涌动 7 人单设备第 1 天
node tools/uitest/ui.mjs 3912 preset script=snv mode=one n=7 with=juggler at=day1     # 梦殒春宵带杂耍艺人第 1 天
node tools/uitest/ui.mjs 3912 preset mode=online n=5 at=night2:imp                    # 线上 5 人第 2 夜轮到小恶魔，说书人 + 小恶魔的手机
```
局面是引擎直接造的房间存档，服务不重启、直接读进内存；页面打开时演出不补播（和断线重连一样），桌面就是那一刻的样子。
之后照常 `look` / `tap` / `seat` / `shot`（下面测试员须知里的命令全都能用）。

### 其他开发者命令（`node tools/uitest/ui.mjs 3912 <命令>`）

- `save <名字>` / `load <名字>` / `saves`：存档点。存房间（服务先写盘）+ 每台设备的身份、网址、尺寸，在 `botc-uitest/saves/` 下，各台 rig 通用；读回时倒计时这类时间整体挪到现在。读档约 3 秒。
- `sync [文件…]`：热更新。把项目里改过的文件同步进快照：只动 `public/` 的刷新页面（约 1 秒），动到 `lib/`、`server.js` 的先让服务写盘再重启（约 2.5 秒），房间和局面都不丢。不给文件就同步全部有差别的（也会带进别的会话改了一半的东西）；只想验自己的就列出文件：`sync public/js/manual.js public/css/hud.css`。
- `fast on|off`：加速。页面当作开了「减少动态效果」（应用自己的开关，演出直接跳到结尾），其余动画 8 倍速。走流程时开，看动画效果前关。天亮演出 6.2 秒 → 1.5 秒。
- `views <设备> [宽x高…]`：一次截几种屏幕，截完回原尺寸。说书人默认 1280x800、375x664、844x390；手机默认 375x664、360x640、844x390。实时改尺寸和按那个尺寸重新加载，量出来的位置一致。
- `measure <设备> <选择器> [样式 / --变量…]`：量位置尺寸和计算样式，例：`measure st .obit outline-color --hole-y`。
- `eval <设备> <JS>`：在页面里跑一段 JS 返回结果。
- `reload [设备]`、`restart`（只重启服务）、`devices`、`drop <设备>`、`status`、`close`。
- 验某个提交而不是工作区：先 `git -c core.autocrlf=false archive <提交> public lib server.js package.json | tar -x -C <草稿目录>`，再 `node tools/uitest/rig.mjs <名字> <端口> src=<草稿目录> [局面参数…]`（后台跑；带了局面参数会先摆好再打印 `RIG READY`）。`sync` 也从那个目录取。

### 给用户看：内置浏览器面板

- **不往 `.claude/launch.json` 加测试服务。** 面板每个文件夹最多 5 个服务，闲置会话的配置会一直占着名额。
- `link st` 给出带说书人密钥的网址，`preview_start {url}` 直接打开就是那个局面（不起新服务，用的是 rig 的）；它还给一行关声音的 JS，用 `javascript_tool` 跑一次。玩家手机用 `link p3`：先打开网站根目录跑那行 JS，再进房（之后 rig 里的 p3 会被顶掉，同一座位只认一台设备）。
- 看完就关：`preview_list` 找到进程号，`preview_stop`。确实需要 launch.json 配置时，名字写清用途，用完 `preview_stop` 并把条目删掉。

## 派测试员

- 每个测试员一套：`node tools/uitest/rig.mjs <名字> <基准端口>`，占三个端口（服务、浏览器调试、控制 = 基准、+1、+2），各人错开（3310、3320、3330…）。
- 它会把当前代码复制一份快照来跑，别的会话同时改代码不影响这一局。改了代码要复验，`sync` 或重起一台。
- 不必每个都从建房玩起：派之前自己用 `preset` 摆到要测的地方（或 `load` 一个存档），告诉测试员控制端口和现在停在哪。
- 给每个测试员写清楚剧本和剧情：按座位发什么角色、每一步做什么、预期看到什么。预期写得越具体，越容易发现结果不对。
- 测试员的报告要逐条核对再转述：看他的截图、查发给玩家的数据、在引擎里复现。常见的误报是把官方规则当成错、把工具的显示格式当成界面问题。
- 运行时的东西都在系统临时目录 `botc-uitest/run-<名字>/` 下（依赖拷在 `botc-uitest/node_modules`，所有 rig 共用；不再用目录联接）。浏览器静音，`close` 时关掉。

# 实测员须知

你要像真人一样，通过**真实页面**把一局《血染钟楼》线上局（智能推进）从建房玩到结束，找出跑不通、点不到、看不懂的地方。
被测的是一个网页应用：一位说书人（电脑）+ 若干玩家（各自的手机）。用哪本剧本、走什么剧情，派你来的人会另外告诉你。

## 硬性规则
- **只能通过 `ui.mjs` 操作页面**（真的鼠标点击、键盘输入）。不许直接调接口、不许用 socket、不许改 localStorage、不许在页面里执行脚本绕过界面。`ui.mjs` 开头「开发者用」那一段的命令（preset、load、sync、eval、measure…）你都不能用。
- **不许改项目代码**，也不用去读项目源码找答案：你是用户，界面上看不懂就是问题，记下来。
- 只用分给你的端口和目录；结束时一定 `close`（关掉你的浏览器和服务）。
- 如实汇报：没做到的写没做到，不确定的写不确定。不要把工具自身的限制写成产品问题（见下面「不算问题的」）。

## 起测试台
派你来的人已经给了你控制端口、局面摆好了的话，跳过这一步。否则在项目根目录、你的 Bash 里（**后台运行**，`run_in_background: true`）：
```
node tools/uitest/rig.mjs <你的名字> <你的基准端口>
```
几秒后它会打印 `RIG READY`，后面带着这次的目录（截图在它下面的 `shots/`）。之后所有操作：
```
node tools/uitest/ui.mjs <控制端口=基准端口+2> <命令> ...
```
命令清单在 `tools/uitest/ui.mjs` 文件开头（先读一遍，只用「开发者用」以上的那些）。最常用：`open` `join` `look` `tap` `seat` `who` `shot` `wait` `errors`。
- 设备名：`st` 是说书人（电脑），`p1` `p2`… 是玩家手机（每台是独立的浏览器身份）。
- `tap` 和 `seat` 之后会自动返回一份 `look`，不用再单独 look。
- 一条 Bash 里可以用 `&&` 连着发几条命令（比如几台手机依次投票），省来回。
- `who` 一行一台设备，带 ★ 的是现在要他操作的人。**夜里每走一步先 `who`。**
- 界面默认是简体中文。按钮文字照屏幕上的写（`look` 里「能点的」列的就是）。
- 截图用 `shot`，再用 Read 看图。**截图要省着用**：只在关键画面、`look` 看不明白、或者发现问题要留证据时截（整局大约 10–15 张）。
- 上传自制剧本：先 `upload st <json 路径>`，再 `tap st 上传剧本`。现成的两本在 `tools/uitest/scripts/`。

## 一局大致怎么走（界面会引导你；哪里引导不清楚，记下来）
1. `open st home` → 等几秒 → 「创建房间」→ 选「线上」。弹出的分享窗关掉。
2. 选剧本（各人任务里写了怎么选）。
3. 玩家进房间：`join p1 名字`、`join p2 名字`…
4. 说书人发角色：点座位会出角色面板，点角色就指定；或者「随机抽取」补齐。然后「开始游戏」（有提醒时看清写了什么，再「照样开始」）。
5. 夜晚：说书人屏幕中间的操作卡一步一步往下走。
   - 内置角色：轮到谁，谁的手机上出选人牌（点座位 → 「确认」），说书人这边确认 / 发送信息。
   - **系统不认识的角色**（自制的、官方但没内置规则的）：说书人卡上是提示词。要选人的，那位玩家手机上有选人牌；选完后说书人卡上可能有「死亡 / 中毒 / 醉酒」的章可以按（按了就当场生效，再按一次收回）；只得知信息的，说书人点「告诉他」打字发过去。然后「下一个」。
   - 「假装叫醒」的卡可以等，也可以直接点继续。
   - 走完到「天亮前确认」→ 天亮。
6. 白天：玩家在自己手机上点别人的座位发起提名，大家在手机上投票，说书人计票 / 结算 / 处决；说书人「结束白天，入夜」。
7. 一直到分出胜负。结束后看结算画面，再点「再来一局」确认能回到准备阶段。

## 每一步都顺手检查
- `look` 输出里的「⚠ 点不到的」：按钮在屏幕外或被挡住。
- 手机上：操作牌有没有盖住座位、最下面的按钮是不是点得到。
- 文字：有没有没翻译成简体的、对不上号的、说给错的人听的（给说书人的话出现在玩家手机上，或者反过来）。
- 玩家手机上**不该看到的信息**（别人的角色、今晚谁死了、说书人的标记）。
- 说书人日志（侧栏「流程」）记的和实际发生的一不一致。
- 每个阶段结束时跑一次 `errors`（页面报错）和 `serverlog`（服务端报错）。

## 不算问题的
- `⏳ 正在播放演出`：整屏动画，这时候点不到是正常的，`wait 3000` 再看，或点「跳过」。
- 弹窗、菜单、选角面板打开时，底下的按钮点不到是正常的。
- 无头浏览器没有声音。
- 网络请求 `ERR_CONNECTION` 之类的日志噪音。

## 汇报格式（最后一条消息，中文）
```
结论：跑通 / 没跑通（卡在哪一步）
走过的流程：一两行一段，夜晚每个角色那一步怎么处理的、结果如何
问题清单（按严重度：卡死 > 结果错误 > 点不到/挡住 > 看不懂/别扭 > 文案）：
  每条：【严重度】设备与屏幕尺寸｜复现步骤｜实际看到的（照抄屏幕原文）｜期望｜截图路径
没测到的：……
```
问题要具体到能复现；一条一个问题。拿不准是不是问题的，单列在「存疑」里。

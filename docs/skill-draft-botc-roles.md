# 血染钟楼魔典：角色技能手册

本手册用于智能推进模式。手动模式不处理角色规则，见 `lib/manual.js`。
当前完整的角色表现表在 `docs/role-behaviors.md`，每条修复由 `tests/roles.test.js` 固定。

## 一、技能设计流程

### 1. 动手前先回答六个问题

1. 什么时候触发？首夜、其他夜、白天、死亡时？顺序号是多少？
2. 玩家要操作什么？不操作时算不算使用？
3. 说书人在每种情况下看到哪张卡？有几个按钮？
4. 谁得到什么信息，什么时候得到？
5. 中毒、醉酒、酒鬼、疯子、隐士、间谍时分别怎样？
6. 信息留在哪里，留多久，会不会过期？

答不全的先查官方，不凭记忆写。

### 2. 服务端怎么接

夜晚角色写在 `lib/night.js` 的 `NIGHT`：

| 字段 | 用途 |
|---|---|
| `choose` | 选几人、能否选自己、死活、不能连选、要不要选角色 |
| `run` | 结算，返回下一步 |
| `decide` | 说书人选完后的结算 |
| `skip` | 今晚不醒 |
| `prep` | 叫醒之前说书人要先定的事（沙巴洛斯反刍） |
| `wakeDead` / `onlyIfDiedTonight` | 死了也醒 / 只有今晚死了才醒 |
| `actor` | 替别人选（理发师死后恶魔选） |
| `stOnly` | 玩家不被叫醒，只有说书人结算 |
| `instant` | 插进来的步骤，不占进度条格子 |

`run` 的返回值决定下一步：

| 返回 | 步骤状态 | 说书人看到 |
|---|---|---|
| `{ form }` | `confirm` | 给信息卡 |
| `{ decide }` | `decide` | 选项卡 |
| `{ note, e }` | 玩家选人后变 `ack` | 结果卡，确认才叫下一位 |
| `{ note, ack: true }` | `ack` | 无人操作但有结果的步骤（镜像双子、教父首夜） |

常用工具：

- `gate()`：行动者失效时停一下，只有「无效」。
- `fires(room, seat)`：被动能力触发判断，失效时自动计入数学家。新被动一律用它，不直接写 `!impaired`。
- `addEff(..., by, { live: true })`：效果跟着来源走，来源死亡、换角色、失去能力就暂停，恢复后接着生效（侍臣、亡骨魔、莽夫、女巫）。
- `actTonight()`：当晚才得到的角色。顺序在后面的当晚行动，只在首夜行动的当晚用一次。
- `rise()`：夜里复活，恢复一次性能力。
- 死后选择：`g.lastWords`（月之子、呆瓜、心上人），入夜前必须答完。

### 3. 说书人卡片规则

- 玩家选完人（含说书人代选）必须停在结果卡，确认后才叫下一位。还要裁定或给信息的不多点一次。
- 结果卡必须写清真实结果，包括自动发生的事（接任者、莽夫、被保护）。说书人不该去日志里找答案。
- 按钮数量按「说书人真有选择权」决定：
  - 一个按钮：结果唯一，包括中毒、醉酒。
  - 两个或多个：隐士 / 间谍登记、官方写「可能」的能力、官方写「说书人选」的目标。
- 所有按钮都没有主次：不用主按钮样式，不带 ✓，不替说书人推荐。两个选项的卡顺序固定。
- 回车不触发任何操作，包括确认框、跳过动画、介绍页、加载页，也不重复点焦点停着的按钮。只有输入框里的回车算提交。
- 结果唯一时服务端要拒绝反选。
- 说书人选人优先点桌上的座位。
- 白天不挡操作的卡放左上角（`corner`），必须确认的放桌子中央。

### 4. 玩家侧规则

- 选人走 `prompt` + 中央牌（`turnPane`），有行动的角色在 `ACTS` 登记图标和话术。
- 玩家看到的动词只描述动作，不暗示结果：恶魔、刺客、教父都写「攻击」，用户否决过「击杀」「想杀」「自刀」「传位」。
- 演出不能透露能力是否成功：成功、被保护、中毒时，玩家收到的数据必须完全相同。
- 夜里的死亡对所有玩家隐藏到天亮，包括死者自己。
- 死因只公开处决、射杀、反噬。其他死法只写「死亡」，数据也不发。
- 玩家看不到夜晚进行到哪一格，服务端不发 `at`。

### 5. 演出规则

- 风格：纸张 + 墨章，四拍节奏。动画在桌面上演，不做在卡片上。
- 自己的技能隆重，不限时长，不挡说书人。说书人的结算轻，1.2 秒以内。
- 得到的信息先在桌子中央停 1.4 秒，再飞走。关于具体座位的结果拆开飞到座位旁，没有座位的才进面板。
- 每个角色有自己的演出，不用连线。不做全屏网点，不做贴脸翻转，不做环形波。
- 不许硬切：新东西有来路，旧东西有去处。
- 被动结算在说书人端用 `ststamp` 盖章（「全场醉酒」「额外一天」「弄臣免死」）。
- 死法各有演出：绞刑架只给真处决，处决没死不褪色并盖「没有死亡」，贞洁者是闪电，猎手是准星和箭，夜里死亡是通用「死亡」。
- 公开开口的能力（造谣者、杂耍艺人、月之子、呆瓜、博学者、艺术家）没有演出。

### 6. 收尾

1. 写进 `tests/roles.test.js`，一条规则一条断言。
2. 更新 `docs/role-behaviors.md` 和 README。
3. 新的裁定写进 `role-rule-rulings` 记忆。
4. 在真实页面走一遍，见第二节。

## 二、怎么用官方规则验证

### 1. 依据的顺序

1. 官方 wiki 的角色页：能力原文、Summary、How to Run、Examples。牌面文字很短，细节在 Summary 和 How to Run，不能只看牌面。
2. 官方术语表和 Rules Explanation。
3. 其他角色页里的交叉说明。例如「刺客打莽夫」写在刺客页，莽夫页没有。
4. 社区资料只作线索，不能写成官方。

两页矛盾时，选写得明确的那一页，把取舍写进裁定表。例：普卡页说毒不能被阻挡，僧侣页和士兵页明确写能挡毒，按后者。

读原文用内置浏览器的 `get_page_text`。`WebFetch` 返回的是模型摘要，`curl` 会被网站拦下。说「官方写明」之前要看到原句。

### 2. 表述要诚实

- 区分三种说法：官方写明、官方没写按通则推出、社区说法。
- 区分三种证据：实际跑过、只读代码、页面实测。回复里要标出来。
- 官方没写时不说「官方是这样」，写「官方没写，我们这样做」。
- 不把自己早先的实现判断说成用户的决定。

### 3. 核对步骤

1. 查该角色页和所有相关角色页。
2. 对照 `lib/night.js`、`lib/rules.js`、`lib/day.js` 的当前代码，不凭记忆。
3. 写探针脚本实际跑：放在 scratchpad，用 `file:///` 导入 `tests/helpers.js`，用完不进仓库。
4. 查「谁得到什么」时，跑多种情况并比较玩家视图的完整 JSON（`viewFor`），要完全相同才算没泄露。
5. 每个能力都过一遍下面的交叉表。
6. 修完后写断言，再跑全量。

### 4. 每个能力都要过的交叉表

| 情况 | 要确认什么 |
|---|---|
| 中毒、醉酒、酒鬼、疯子 | 只有「无效」，一次性能力照样用掉，信息类可给假 |
| 僧侣、士兵、旅店老板、茶艺师 | 恶魔的所有负面效果都挡，包括毒和变身 |
| 镇长替死 | 替死算恶魔杀的，祖母、贤者、亡骨魔、方古要照常 |
| 隐士、间谍 | 每次检测由说书人决定，不是固定身份，死后仍可登记 |
| 涡流 | 镇民只能得到错误信息 |
| 复活 | 能力和一次性能力都回来，后面的当晚醒 |
| 换角色 | 陈旧步骤跳过，新角色是否当晚行动，旧效果是否失效 |
| 能力来源死亡或失效 | 它造成的效果要不要结束 |
| 多杀恶魔 | 中途的裁定是否被吞掉 |
| 数学家 | 这次失效算不算，用 `fires` |
| 夜里死 / 白天死 | 什么时候算「知道自己死了」 |
| 游戏结束 | 裁定和死后选择是否卡住流程 |

### 5. 测试和实测

- 规则：`npm test`。随机对局 `mix.test`、`engine.test` 至少连跑多次，偶发失败必须抓到原因。
- 页面：说书人和玩家都要看。桌面 + 手机 375×812，手机还要查短屏和横屏：375×553、390×664、360×640、320×568、844×390、932×430。
- 手机按钮要做命中测试（`elementFromPoint`）。
- 动画要看到最终画面，只看数据不算验证过。
- 难凑的状态才进演示页，打开游戏能看到的直接在真实局验证。

## 三、谁的信息能确定为真、能保留

先分清三件事：事实发生过、信息来源可靠、结论成立。「你选择了 X」是事实，不代表技能成功。

### 1. 一定是真的，可以当事实保留

| 信息 | 谁拿到 | 为什么可信 | 留存 |
|---|---|---|---|
| 死讯、提名、投票、处决结果、开枪结果 | 所有人 | 公开事件 | 游戏日志，整局 |
| 公开死法（处决、射杀、反噬） | 所有人 | 公开事件 | 座位章 |
| 「你选择了 X」 | 本人 | 自己的操作 | 面板整局；目标标记当夜到次日白天 |
| 爪牙牌、外来者牌 | 本人 | 这三本剧本里没有假爪牙、假外来者 | 面板 |
| 爪牙得知恶魔和同伴 | 爪牙 | 不是角色能力，中毒也照给 | 头像换成阵营牌，整局 |
| 真恶魔得知爪牙、疯子是谁、三个伪装 | 真恶魔 | 同上 | 头像换阵营牌、伪装卡 |
| 瘋子选了谁 | 真恶魔 | 说书人直接告知 | 面板 |
| 「你现在是 X」（传位、舞蛇人、麻脸巫婆、理发师、哲学家） | 本人 | 只有真的变了才发 | 面板，角色牌同步 |
| 陈营变化（莽夫） | 本人 | 只有真的变了才发 | 面板 + 角色名旁「现为邪恶 / 善良」 |
| 被驱魔人选中 | 恶魔 | 驱魔人有能力时才发 | 面板，标记驱魔人座位 |
| 被洗脑师选中 | 目标 | 洗脑师有能力时才发 | 面板 |

注意：

- 公开事件只说明发生了什么，不说明原因。没人死可能是僧侣、士兵、恶魔中毒。
- 爪牙看到的恶魔是当时的真相。传位后其他爪牙不会被告知，旧标记仍留着。
- 僵怖首次死亡会被公开成死亡，其实还活着。

### 2. 本人不能确定，但系统要照常展示

| 信息 | 为什么不能确定 |
|---|---|
| 镇民角色牌 | 可能是酒鬼 |
| 恶魔角色牌 | 剧本有疯子时可能是疯子 |
| 爪牙名单、伪装（持恶魔牌的人） | 如果是疯子，全是假的，爪牙可以是任何人，伪装可以在场 |
| 自己的能力是否生效 | 玩家永远不知道自己中毒或醉酒 |

系统不能为这类玩家做任何区别显示，否则就泄露了身份。疯子的假信息和真恶魔的信息样式必须相同。

### 3. 能力得到的信息，都可能是假的

洗衣妇、图书管理员、调查员、厨师、共情者、占卜师、送葬者、守鸦人、祖母、侍女、钟表匠、筑梦师、卖花女孩、城镇公告员、神谕者、女裁缝、杂耍艺人、贤者、数学家、间谍。

可能出错的原因：

- 中毒、醉酒、酒鬼：说书人可以给假信息，也可以给真的。
- 涡流：镇民的信息必须是错的。
- 隐士、间谍登记：信息「合规」，但和真实角色不同。
- 占卜师：红鲱鱼被当作恶魔。

所以这类信息只能保留，不能标成事实：

- 两人之一、筑梦师：角色标记带 `?`。
- 占卜师：写「有恶魔？」「非恶魔」。
- 守鸦人、送葬者、祖母：角色标记不带 `?`，因为这是得到的答案，但仍可能是假信息。
- 给说书人看的「真」只表示系统真相，绝不发给玩家。

### 4. 留存规则

| 位置 | 内容 | 期限 |
|---|---|---|
| 玩家面板 | 所有私密信息 | 整局。记录满 600 条先丢闲聊，再丢公告，私密信息最后 |
| 座位信息标记 | 信息带的角色、是否 | 整局。间谍每晚只保留最后一次魔典 |
| 阵营牌头像 | 爪牙、恶魔互认 | 整局 |
| 行动标记 | 自己今晚选的人 | 当夜到次日白天 |
| 伪装卡 | 恶魔 | 换阵营前 |
| 玩家备注、猜测 | 本人 | 存本机，新局清空 |
| 说书人座位标记 | 中毒、醉酒、保护、诅咒、瘋狂：角色、蓄力、额外一天 | 随效果结束 |
| 流程日志 | 说书人 | 整局，增量发送 |

演出没播完时，标记和面板行先渲染但隐藏（`.mk-held`），演出飞到它的位置后再显示。

## 四、已确定的规则裁定

| 情况 | 裁定 |
|---|---|
| 中毒、醉酒 | 没有能力，说书人不能让它生效，只能给假信息 |
| 猎手 | 整局一枪，打空或中毒也用掉；任何人都可以假装开枪；复活后子弹回来 |
| 贞洁者 | 必定反噬时 30 秒或计票前自动；健康贞洁者被间谍提名才二选一 |
| 小恶魔自杀 | 当晚立即传位；死亡前 ≥5 人存活时红唇女郎必须接任；不足时说书人选存活爪牙；新小恶魔当晚不行动 |
| 小恶魔自杀失败 | 玩家当晚不知道，天亮才看出 |
| 没有存活爪牙 | 走完当晚，天亮判善良胜（官方没写） |
| 隐士接任 | 不允许（只有社区说法） |
| 镇长 | 能力正常才替死；死人、士兵、被僧侣保护的不能替死；多杀恶魔也问 |
| 送葬者 | 处决致死才有信息 |
| 僧侣 | 不知道保护是否成功 |
| 普卡 | 僧侣、士兵挡毒 |
| 莽夫 | 先醉酒后结算；阵营变了才告知，只说阵营；健康刺客不受影响，莽夫死亡并转邪恶 |
| 教授 | 官方写明：复活者恢复能力，用过的一次性能力也回来；顺序在教授之后的当晚醒；首夜或「开局得知」的能力，教授睡下后马上再用一次 |
| 沙巴洛斯反刍 | 官方写明，能力恢复规则同教授。唤醒他之前反刍，有可反刍者时说书人先选；他没有能力时不反刍；首夜角色当场用，然后才叫醒他；反刍的人当晚又被选中会再死一次 |
| 哲学家 | 后夜选首夜角色，当晚用一次 |
| 亡骨魔 | 邻居由说书人选；失去能力后解毒，死爪牙不再醒；主谋相克例外 |
| 侍臣 | 失去能力时对方清醒，恢复后再醉；死亡也清醒（裁定） |
| 女巫 | 失去能力诅咒失效（裁定）；≤3 人时不再行动 |
| 麻脸巫婆 | 新角色顺序在后的当晚行动；造出恶魔时说书人连选死者 |
| 心上人 | 说书人选谁醉酒 |
| 月之子、呆瓜 | 知道自己死了就弹卡，公开选人，入夜前答完；选中隐士 / 间谍时说书人定 |
| 主谋 | 不公开，只有说书人有章 |
| 吟游诗人 | 不公开，说书人有章 |
| 修补匠、畸形秀演员 | 不提醒，能力写「可能」 |
| 博学者、艺术家 | 白天小圆牌提醒说书人 |
| 杂耍艺人 | 第一个白天公开猜，系统算数字 |
| 假装叫醒 | 只有今晚第一格空着时，60 秒 |
| 数学家 | 数字系统算好并标「真」，仍可改；被挡下的成功保护不算 |

## 五、工程上的坑

- 文件混用 CRLF 和 LF，脚本替换要先判断换行，否则匹配不到还会以为改好了。
- 同一文件夹常有其他会话在改。改前重新读，只碰自己的部分，报告时分开说明，提交时不要带上别人的改动。测试失败先看是不是对方改到一半。
- 内置预览有 5 个服务器的上限。占满时用终端面板单开端口，并设独立的 `DATA_DIR`。
- 浏览器面板隐藏时不出帧，截图可能全黑。先切到该标签再等。
- `startNight` 会立刻跑第一步，测试里要在之后重建 `g.queue`，再清 `g.step`、`g.beat` 后 `run`。
- `glyph.js` 依赖浏览器，Node 测试不能导入。
- `room.test` 的端口范围要避开 Windows 保留段，用 `netsh interface ipv4 show excludedportrange protocol=tcp` 查。
- 夜里 `killSeat` 不判胜负，天亮才判。
- `fx` 事件的 `aud` 决定谁看到，新事件要确认不会发给不该看到的人。
- 新加 `tell` 时确认能力失效时不会误发。
- 改界面文字后确认繁简表 `public/js/t2s.js` 有这个字，它由 `tools/gen-t2s.py` 生成。
